Jak se věci hýbou

Postavička, která běží, skáče a nepropadne podlahou, se skládá ze tří kousků: pohybu, gravitace a kolizí. Žádné kouzlo, jen pár řádků, které se opakují šedesátkrát za sekundu.

Každý kousek si nejdřív vyzkoušíš samostatně a nakonec je spojíš na hřišti, kde si můžeš sám vyladit, jak se postava ovládá. Ukázky kódu jsou v GameMakeru, přepínač nabízí i Godot, Unity a Scratch.

SouřadniceKde věc je. Pohyb je jen změna x a y v každém snímku. RychlostO kolik pixelů se věc posune za jeden snímek. Zrychlení a třeníJak rychle se rozjede a zastaví. Dělá pohyb „těžkým“ nebo „lehkým“. GravitaceKaždý snímek přidá kousek rychlosti směrem dolů. KolizeZjištění, jestli se dvě věci překrývají. Řešení kolizeCo udělat, aby postava stála u zdi a ne v ní.
Krok 1 · Souřadnice a snímky

Pohyb je série malých skoků

Každá instance má polohu x a y v pixelech. Bod (0, 0) je v levém horním rohu scény. x roste doprava a y roste dolů, ne nahoru jako v matematice.

Hra se překresluje zhruba 60× za sekundu. Každému překreslení se říká snímek (frame) a v každém snímku se spustí událost Step. Když v ní napíšeš x += 3, instance se každý snímek posune o 3 pixely doprava. Za sekundu urazí 180 pixelů a oku to splyne v plynulý pohyb.

Jako kreslená knížka: každá stránka je jen o kousek jiná.

GameMaker počítá rychlost v pixelech za snímek. Godot a Unity častěji v jednotkách za sekundu a násobí ji časem snímku (delta). Rychlost 3 px/snímek při 60 FPS je totéž co 180 px/s.

Poloha je ve vestavěných proměnných x a y. Pohyb píšeš do události Step. GameMaker má i vestavěné hspeed/vspeed, které posouvají instanci samy, ale vlastní proměnné máš víc pod kontrolou.

// Create
hsp = 3;   // vodorovná rychlost v px za snímek
vsp = -1;  // svislá rychlost (záporná = nahoru!)

// Step
x += hsp;
y += vsp;

Poloha uzlu je position (Vector2). Osa y také roste dolů. Pohyb násob delta (doba snímku v sekundách), aby byl stejně rychlý na pomalém i rychlém počítači.

var rychlost = Vector2(180, -60)   # px za sekundu

func _process(delta):
    position += rychlost * delta

Poloha je transform.position (Vector3). Pozor: v Unity y roste nahoru a jednotkou nejsou pixely, ale „metry“ (obvykle 1 jednotka = 100 px spritu).

public Vector2 rychlost = new Vector2(1.8f, 0.6f);   // jednotek za sekundu

void Update() {
    transform.position += (Vector3)(rychlost * Time.deltaTime);
}

Ve Scratchi je bod (0, 0) uprostřed scény a y roste nahoru. Scéna sahá od x −240 do 240 a od y −180 do 180.

Krok 2 · Rychlost, zrychlení a tření

Rozjezd a brzdění dělají pocit z ovládání

Nejjednodušší ovládání: držíš šipku, postava jede plnou rychlostí. Pustíš ji a postava stojí. Funguje to, ale působí to tvrdě, jako by postava neměla žádnou váhu.

Lepší je měnit rychlost postupně. Zrychlení říká, o kolik rychlost přibude v každém snímku, dokud držíš šipku. Tření říká, o kolik ubude, když šipku pustíš. Malé tření = klouže to jako po ledu. Velké tření = zastaví se hned.

Graf ukazuje rychlost hsp obou postav za poslední 4 sekundy. Horní postava skáče mezi 0 a maximem, dolní se rozjíždí a dobíhá.

keyboard_check vrací 1, když je klávesa držená, jinak 0. Rozdíl pravé a levé šipky dá směr −1, 0 nebo 1.

var smer = keyboard_check(vk_right) - keyboard_check(vk_left);

if (smer != 0) {

    hsp = clamp(hsp, -max_rychlost, max_rychlost); // nepřekroč maximum
} else {

move_toward(a, b, krok) posune hodnotu a k b nejvýš o krok. Na rozjezd i brzdění stačí jedna funkce.

const MAX_RYCHLOST = 240.0   # px/s
const ZRYCHLENI = 1080.0     # px/s za sekundu
const TRENI = 540.0

func _physics_process(delta):
    var smer = Input.get_axis("ui_left", "ui_right")
    if smer:
        velocity.x = move_toward(velocity.x, smer * MAX_RYCHLOST, ZRYCHLENI * delta)
    else:
        velocity.x = move_toward(velocity.x, 0, TRENI * delta)
    move_and_slide()

Stejný princip s Mathf.MoveTowards. U postavy s Rigidbody2D nastavuješ linearVelocity (ve starších verzích Unity velocity).

Vector2 v = rb.linearVelocity;
v.x = Mathf.MoveTowards(v.x, cil, krok);
rb.linearVelocity = v;

Krok 3 · Gravitace a skok

Gravitace je jeden řádek kódu

Gravitace v plošinovce není nic složitého: v každém snímku přičteš ke svislé rychlosti vsp malé číslo. Postava padá čím dál rychleji, stejně jako kámen.

Skok je opak: jednou nastavíš vsp na záporné číslo (nahoru) a gravitace ho postupně „sežere“. Postava zpomalí, na vrcholu se na chvilku zastaví a začne padat. Vznikne oblouk, kterému se říká parabola.

Aby postava nepadala nekonečně rychle, rychlost pádu se omezí maximem.

Výška skoku je přibližně síla² / (2 × gravitace). Při síle 10 a gravitaci 0,5 je to asi 100 px. Dvojnásobná síla skoku dá čtyřnásobnou výšku. Zkus to.

GameMaker má i vestavěnou proměnnou gravity, ale v plošinovkách se skoro vždy píše vlastní, aby šla gravitace vypnout na zemi a omezit maximem.

vsp = min(vsp + gravitace, max_pad);   // gravitace + max. rychlost pádu

if (na_zemi && keyboard_check_pressed(vk_space)) {
    vsp = -sila_skoku;                 // záporně = nahoru
}
if (keyboard_check_released(vk_space) && vsp < 0) {
    vsp *= 0.5;                        // krátký skok
}
y += vsp;

CharacterBody2D má rychlost ve velocity. Gravitace projektu (Project Settings → Physics → 2D) se získá přes get_gravity().

const SILA_SKOKU = -600.0

func _physics_process(delta):
    if not is_on_floor():
        velocity += get_gravity() * delta
    if Input.is_action_just_pressed("ui_accept") and is_on_floor():
        velocity.y = SILA_SKOKU
    if Input.is_action_just_released("ui_accept") and velocity.y < 0:
        velocity.y *= 0.5
    move_and_slide()

S komponentou Rigidbody2D gravitaci počítá fyzika sama, sílu nastavíš polem Gravity Scale. Skok je jednorázový „kopanec“ nahoru.

void Update() {
    if (Input.GetButtonDown("Jump") && naZemi) {
        rb.linearVelocity = new Vector2(rb.linearVelocity.x, silaSkoku);   // + je nahoru
    }
    if (Input.GetButtonUp("Jump") && rb.linearVelocity.y > 0) {
        rb.linearVelocity = new Vector2(rb.linearVelocity.x, rb.linearVelocity.y * 0.5f);
    }
}

Krok 4 · Detekce kolize

Dotýkají se? Stačí čtyři porovnání

Kolize znamená, že se dvě věci překrývají. Engine to většinou nepočítá z obrázku, ale z kolizní masky, což bývá obyčejný obdélník kolem postavy (znáš ho ze spritu v lekci 1). Říká se mu bounding box nebo AABB.

Dva obdélníky se překrývají, právě když platí všechny čtyři podmínky najednou: A začíná před koncem B, A končí za začátkem B, a totéž svisle. Když neplatí jediná, mezi nimi je mezera.

Obdélník je rychlý, ale nepřesný. Zkus postavy přisunout rohy k sobě: obdélníky se překrývají, i když se postavy nedotýkají.

Masku nastavíš v Sprite Editoru (Collision Mask). Hranice masky instance najdeš v bbox_left, bbox_right, bbox_top, bbox_bottom. Nejčastěji ale použiješ hotovou funkci:

// byla by kolize, kdybych stál o 4 px vpravo?
if (place_meeting(x + 4, y, obj_zed)) { ... }

// kterou instanci jsem zasáhl?
var s = instance_place(x, y, obj_slime);
if (s != noone) s.hp -= 1;

// nebo událost Collision → obj_mince v objektu hráče

Tvar kolize je samostatný uzel CollisionShape2D (obdélník, kruh, kapsle…). Na „dotkl se mě někdo?“ slouží Area2D a jeho signál body_entered.

# skript na mince (Area2D), signál body_entered připojený v editoru
func _on_body_entered(body):
    if body.name == "Hrac":
        queue_free()   # mince zmizí

Tvar kolize je komponenta BoxCollider2D, CircleCollider2D a další. Collider se zaškrtnutým Is Trigger jen hlásí dotyk, jinak se tělesa od sebe odráží.

void OnTriggerEnter2D(Collider2D other) {
    if (other.CompareTag("Player")) {
        Destroy(gameObject);   // mince zmizí
    }
}

Krok 5 · Řešení kolize

Stůj u zdi, ne ve zdi

Vědět, že se něco překrývá, nestačí. Musíš rozhodnout, co s tím. Pro zdi a podlahu se osvědčil jednoduchý postup: než se pohneš, podívej se, kam se chystáš. Když by tam byla zeď, přisuň se k ní po jednom pixelu a zastav.

Níž jsou tři postavičky, které běží proti zdi a každá to řeší jinak. Pak zkus rychlost nad 72 (třeba 80) a sleduj, co se stane se všemi třemi.

Tunelování. Hra kontroluje kolize jen v jednotlivých snímcích. Postava mezi nimi „skáče“ a neprochází místy uprostřed. Když je skok delší než tloušťka zdi plus šířka postavy (tady 32 + 40 = 72 px), cílové místo může ležet až za zdí. Kontrola cíle pak nic nenajde a projdou i přístupy 2 a 3. Pomůže omezit maximální rychlost, rozdělit rychlý pohyb na víc menších kroků za snímek, nebo nechat engine kontrolovat celou dráhu: v Unity Collision Detection: Continuous.

GameMaker: přisouvání přes while, nebo move_and_collide?

Novější verze GameMakeru mají hotovou funkci move_and_collide(dx, dy, obj). Nedělá ale přesně totéž co ruční přisouvání. Pohyb rozdělí na několik dílčích kroků (výchozí jsou 4) a po každém zkontroluje kolizi. Když narazí, zkusí se pohnout kolmo, takže postava sklouzne po svahu nebo vyjde malý schod.

Klasický postup: vodorovně a svisle zvlášť. Kód je delší, ale vidíš v něm, co se přesně děje.

// vodorovně
if (place_meeting(x + hsp, y, obj_zed)) {
    while (!place_meeting(x + sign(hsp), y, obj_zed)) {
        x += sign(hsp);   // přisouvej po 1 px

    hsp = 0;

x += hsp;

// svisle

    }

Totéž s move_and_collide. Funkce sama posune x i y, ale rychlosti nastavuješ ty:

// pohyb s kolizí: 4 dílčí kroky, vodorovně nejvýš o max_rychlost
move_and_collide(hsp, vsp, obj_zed, 4, 0, 0, max_rychlost, -1);

// rychlosti funkce nemění, vynuluj je sám
if (vsp > 0 && place_meeting(x, y + 1, obj_zed)) vsp = 0;            // dopadl na zem
if (vsp < 0 && place_meeting(x, y - 1, obj_zed)) vsp = 0;            // narazil hlavou
if (hsp != 0 && place_meeting(x + sign(hsp), y, obj_zed)) hsp = 0;   // narazil do zdi

GameObject se SpriteRenderer, Rigidbody2D (Freeze Rotation Z) a BoxCollider2D. Podlaha má jen collider. Gravitaci řeší Rigidbody2D, kontrolu země malý paprsek dolů.

using UnityEngine;

public class Hrac : MonoBehaviour {
    public float maxRychlost = 5f, zrychleni = 40f, treni = 30f, silaSkoku = 12f;
    public LayerMask zem;
    Rigidbody2D rb;

    void Awake() { rb = GetComponent<Rigidbody2D>(); }

    void Update() {
        bool naZemi = Physics2D.Raycast(transform.position, Vector2.down, 0.6f, zem);
        Vector2 v = rb.linearVelocity;

        float smer = Input.GetAxisRaw("Horizontal");
        float krok = (smer != 0 ? zrychleni : treni) * Time.deltaTime;
        v.x = Mathf.MoveTowards(v.x, smer * maxRychlost, krok);

        if (Input.GetButtonDown("Jump") && naZemi) v.y = silaSkoku;
        if (Input.GetButtonUp("Jump") && v.y > 0) v.y *= 0.5f;

        rb.linearVelocity = v;
    }
