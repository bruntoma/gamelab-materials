Krok 1 · Spritesheet

Všechny pózy na jednom archu

V lekci 1 měl sprite několik snímků. Grafici je ale většinou nekreslí do samostatných souborů. Všechny pózy postavy dají do jednoho obrázku a rozmístí je v pravidelné mřížce. Takovému obrázku se říká spritesheet (arch spritů).

Engine pak potřebuje vědět, jak arch rozřezat: jak velký je jeden snímek, kde mřížka začíná (odsazení, offset) a jak široká je mezera mezi snímky (separace). Mezery grafici dělají schválně, aby se při zvětšení nepřelévaly barvy ze sousedních snímků.

Každý řádek archu bývá jedna animace. V GameMakeru z každého řádku uděláš samostatný sprite: spr_hrac_stoji, spr_hrac_beh, spr_hrac_skok a tak dál. Ty použijeme v celé lekci.

Vlevo arch zvětšený 8×. Barevné rámečky ukazují, jak ho engine rozřeže při zvolených hodnotách. Vpravo je animace složená z vyříznutých kousků.

Který řádek

▦

Pixel art je rozmazaný? Engine obrázky při zvětšení vyhlazuje. U pixelové grafiky to vypni. GameMaker: Game Options → Graphics → Interpolate colours between pixels odškrtnout. Godot: Project Settings → Rendering → Textures → Default Texture Filter: Nearest. Unity: u obrázku Filter Mode: Point a Compression: None.

V Sprite Editoru: Image → Import Strip Image. Nastavíš počet snímků, velikost snímku, odsazení (Pixel Offset) a mezery (Separation), stejně jako v ukázce. Řádek vybereš přes Vertical Cell Offset. Z každého řádku udělej vlastní sprite a všem dej stejnou velikost plátna a stejný origin (Bottom Centre), jinak bude postava při přepnutí animace poskakovat.

// v kódu se na snímky ptáš takhle:
var pocet = sprite_get_number(spr_hrac_beh);   // 4 snímky
var sirka = sprite_get_width(spr_hrac_beh);    // 8 px

// pás snímků se dá načíst i za běhu (třeba pro módy):
var s = sprite_add("hrac_beh.png", 4, false, false, 4, 10);

Animace má uzel AnimatedSprite2D v sadě SpriteFrames. Tlačítko s mřížkou Add frames from sprite sheet arch rozřeže: nastavíš počet snímků vodorovně a svisle, velikost, separaci a offset a pak klikáním vybereš snímky, které patří do animace. Na jednoduché věci stačí i Sprite2D:

$Sprite2D.hframes = 4   # sloupců v archu
$Sprite2D.vframes = 4   # řádků
$Sprite2D.frame = 5     # 2. řádek, 2. snímek (počítá se od 0)

U obrázku nastav Sprite Mode: Multiple, otevři Sprite Editor a zvol Slice → Grid By Cell Size: velikost snímku, Offset a Padding (mezera). Unity vytvoří samostatný sprite pro každý snímek. Když jich víc označíš a přetáhneš do scény, rovnou z nich udělá animační klip.

// všechny rozřezané snímky (obrázek musí být ve složce Resources)
Sprite[] snimky = Resources.LoadAll<Sprite>("hrac_sheet");

Scratch archy neumí. Každý snímek nahraj jako samostatný kostým (Nahrát kostým umí vybrat víc souborů najednou). Arch rozřežeš třeba v online editoru Piskel. Kostýmy pojmenuj podle animace: beh1, beh2…

Krok 2 · Tileset a tilemapa

Level jako tabulka čísel

V lekci 2 jsme podlahu skládali z instancí obj_zed. U větší scény by to byly stovky objektů a každý stojí výkon. Hry proto skládají svět z dlaždic (tiles): malých čtverců stejné velikosti, u nás 32 × 32 px.

Tileset je spritesheet dlaždic. Každá dlaždice v něm má své číslo. Tilemapa je mřížka přes celou scénu a v každém políčku je jen číslo dlaždice, která se tam nakreslí. 0 znamená prázdno. Celý level je tak tabulka čísel. Uložit ji je snadné a kreslí se rychle.

Ruční skládání krajů a rohů by byla otrava. Proto enginy umí autotiling: ty jen maluješ „tady je zem“ a engine podle sousedů sám vybere správnou dlaždici. Najeď myší na zem a uvidíš, jak to počítá.

Vyjde číslo 0 až 15 a každé odpovídá jedné dlaždici. 16 kombinací = 16 dlaždic v tilesetu. Sady se 47 dlaždicemi navíc hlídají rohové sousedy, takže umí i vnitřní rohy.

Kolize s tilemapou

Pohybový skript z lekce 2 se ptal place_meeting(x, y, obj_zed). V GameMakeru se stejná funkce umí zeptat i tilemapy: místo objektu jí předáš ID vrstvy s dlaždicemi a každá neprázdná dlaždice je pak pevná. V pohybovém kódu se tak změní jen jedno slovo.

Vytvoř asset Tile Set, vyber mu sprite s dlaždicemi a nastav velikost dlaždice, offset a separaci (jako u archu). Autotiling se nastavuje v Tile Set editoru v části Auto Tiling. Pak v Room Editoru přidej vrstvu typu Tiles, pojmenuj ji třeba Zem, přiřaď jí tileset a maluj. Dlaždice 0 je v GameMakeru vždy prázdná.

// Create
zem = layer_tilemap_get_id("Zem");   // vrstva Tiles se jménem Zem

// Step: kolize jako v lekci 2, jen místo obj_zed je tilemapa
if (place_meeting(x + hsp, y, zem)) {
    while (!place_meeting(x + sign(hsp), y, zem)) x += sign(hsp);
    hsp = 0;
}
// zdi i dlaždice najednou: place_meeting(x, y, [obj_zed, zem])

// čtení a zápis dlaždic
var t = tilemap_get(zem, 5, 3);                 // dlaždice ve sloupci 5, řádku 3
tilemap_set(zem, 0, 5, 3);                      // smaž ji
var pod_nohama = tilemap_get_at_pixel(zem, x, y + 1);

Uzel TileMapLayer s prostředkem TileSet. Kolize přidáš v TileSetu jako Physics Layer a na dlaždice nakreslíš tvar. Autotiling se jmenuje Terrains (Terrain Set v režimu Match Corners and Sides). CharacterBody2D s move_and_slide() pak na dlaždicích stojí sám, pohybový kód se nemění.

@onready var zem: TileMapLayer = $Zem

func _ready():
    var bunka = zem.local_to_map(zem.to_local(global_position))   # pixel → buňka
    print(zem.get_cell_source_id(bunka))                         # -1 = prázdno
    zem.set_cell(Vector2i(5, 3), 0, Vector2i(2, 1))   # zdroj 0, dlaždice ze sloupce 2, řádku 1
    zem.erase_cell(Vector2i(5, 3))

GameObject → 2D Object → Tilemap → Rectangular. Dlaždice maluješ v okně Tile Palette. Pro kolize přidej k tilemapě Tilemap Collider 2D (a pro hladký povrch ještě Composite Collider 2D). Autotiling dělá Rule Tile z balíčku 2D Tilemap Extras. Pozor, v Unity roste y buněk nahoru.

using UnityEngine.Tilemaps;

public Tilemap zem;
public TileBase trava;

void Start() {
    Vector3Int bunka = zem.WorldToCell(transform.position);
    TileBase t = zem.GetTile(bunka);                 // null = prázdno
    zem.SetTile(new Vector3Int(5, 3, 0), trava);
    zem.SetTile(new Vector3Int(5, 3, 0), null);      // smazat
}

Krok 3 · Level design

Hráč se má učit hraním

Level design je navrhování úrovní: kam dát plošiny, propasti, nepřátele a mince a co se v nich hráč naučí. Dobrý level hráči nic nevysvětluje textem. Postaví ho do situace, ve které na pravidlo přijde sám.

  • Měř podle postavy. Výška a dálka skoku z lekce 2 určují, jak vysoký smí být schod a jak široká propast. Těmto číslům se říká metriky. Zjisti je dřív, než začneš kreslit.
  • Nauč, procvič, zkomplikuj. Novou věc ukaž nejdřív bez trestu, pak s rizikem a nakonec ve spojení s něčím dalším.
  • Čitelnost. Co je pevné, musí vypadat pevně. Pozadí ztlum, popředí nech kontrastní. Stejná věc vypadá v celé hře stejně.
  • Veď hráče. Řada mincí ukazuje cestu i správný oblouk skoku. Mince na nedostupném místě láká hledat, jak se tam dostat.
  • Rytmus. Střídej napětí a oddech. Po těžké pasáži dej bezpečné místo.
Metriky skokuobj_hrac z lekce 2 · dlaždice 32 pxKlikni, kam postavit plošinu

Tečky jsou dráha skoku v plné rychlosti, snímek po snímku. Zelená plocha je všechno, kam postava může doskočit, když ve vzduchu přibrzdí. Šipkami můžeš plošinu posouvat.

Nech rezervu. Skok na samé hraně dosahu zvládne jen ten, kdo hru zná nazpaměť. Schody a propasti navrhuj aspoň o půl dlaždice menší, než je maximum. Maximum si nech na místa, která mají být schválně těžká. A když ladíš gravitaci nebo sílu skoku, změní se metriky a s nimi i celý level.

Nauč, procvič, zkomplikuj

Stejný skok třikrát po sobě, pokaždé s jiným rizikem. V prvním hráč nic neztratí, takže zkouší. Ve druhém už ví, co dělat. Ve třetím přidáš novou věc, třeba nepřítele, a skok, který už umí, dostane nový smysl.

Tři úseky levelustejná mezera, rostoucí riziko
  1. NaučMezera má dno. Spadneš a vylezeš. Mince nad ní ukazují oblouk skoku.
  2. ProcvičStejná mezera, ale bez dna. Hráč už ví, jak na to, teď to musí zvládnout.
  3. ZkomplikujZa mezerou hlídkuje slizoun. Skok je stejný, jen musíš vybrat správnou chvíli.
Krok 4 · Animace

Snímky, rychlost a smyčka

Sprite přehrává své snímky dokola. Který snímek se zrovna kreslí, určuje proměnná image_index. Engine k ní v každém snímku hry přičte kousek podle rychlosti animace. Je to desetinné číslo a kreslí se snímek podle celé části: 2,33 znamená snímek 2.

Rychlost má dvě části. FPS spritu nastavíš v Sprite Editoru: kolik snímků animace se přehraje za sekundu. image_speed je násobek: 1 = normálně, 0,5 = poloviční rychlost, 0 = stop.

Pozor na klouzání nohou. Když postava běží rychle a nohy se hýbou pomalu, vypadá to, jako by bruslila. Pomůže svázat rychlost animace s rychlostí pohybu.

Některé animace se nemají opakovat: dopad, útok, smrt. Když animace dojede na konec, GameMaker spustí událost Animation End. V ní animaci zastavíš nebo přepneš na jinou.

FPS nastavíš v Sprite Editoru vlevo nahoře. V kódu pracuješ s vestavěnými proměnnými instance:

sprite_index = spr_hrac_beh;   // který sprite
image_index = 0;               // od kterého snímku
image_speed = 0.5;             // poloviční rychlost
// image_number = počet snímků (jen ke čtení)

// ===== Animation End =====
if (sprite_index == spr_hrac_dopad) {
    image_speed = 0;
    image_index = image_number - 1;   // zůstaň na posledním snímku
}

Každá animace v SpriteFrames má vlastní FPS a přepínač Loop. Konec neopakované animace ohlásí signál animation_finished.

@onready var anim: AnimatedSprite2D = $AnimatedSprite2D

func _ready():
    anim.play("beh")
    anim.speed_scale = 0.5               # poloviční rychlost
    anim.animation_finished.connect(_on_konec)

func _on_konec():
    if anim.animation == "dopad":
        anim.play("stoji")

Animační klip (Window → Animation) má Samples (snímky za sekundu) a zaškrtávátko Loop Time. Klipy přehrává komponenta Animator.

Animator anim = GetComponent<Animator>();
anim.Play("Beh");    // spusť stav Beh
anim.speed = 0.5f;   // poloviční rychlost

Animace je přepínání kostýmů. Rychlost určuje čekání: 0,1 s mezi kostýmy = 10 snímků za sekundu.

Krok 5 · Ovládání animací

Pohyb rozhoduje, animace se jen dívá

Máš pohybový skript z lekce 2 a sprity pro stání, běh, skok, pád a dopad. Jak zařídit, aby se přepínaly ve správnou chvíli a aby se v kódu dalo vyznat i za měsíc?

APřímo v pohybu

K řádkům pohybu dopíšeš sprite_index = …, třeba tam, kde se testuje šipka. Animace se pak řídí tím, co hráč mačká, ne tím, co postava opravdu dělá.

rychle napsané, ale chybové a čím dál zamotanější

BZvlášť v End Step

Pohybový kód zůstane beze změny. Výběr animace je v samostatné události, která běží až po pohybu a kolizích. Jen se podívá na výsledek: jsem na zemi? jaké je hsp a vsp?

doporučený základ

CStavový automat

B s pamětí. Proměnná stav si pamatuje, co postava dělá, a mění se jen podle jasných pravidel. Hodí se, jakmile přibudou animace, které se musí dohrát, třeba dopad nebo útok.

Kód obj_hrac

Každé okno je jedna událost objektu obj_hrac. Zkopíruj ho a vlož do stejnojmenné události v GameMakeru. Řádky, které se v tomhle snímku hry zrovna provedly, svítí.

Proč zrovna End Step

GameMaker v každém snímku spouští události v pevném pořadí. Když dáš výběr animace do End Step, máš jistotu, že pohyb i kolize už proběhly a hsp, vsp i poloha jsou pro tenhle snímek konečné. Animace pak ukazuje, co se opravdu stalo, ne co se hráč pokusil udělat.

  1. Begin StepTady nic nepotřebujeme.
  2. StepPohyb z lekce 2: vstup, rychlost, gravitace, kolize. Beze změny.
  3. End StepPřečti hsp, vsp, na_zemi a vyber sprite.
  4. Animation EndJen když animace dojela na konec. Ukončí dopad.
  5. DrawEngine nakreslí sprite_index, snímek image_index.
0

Nová animace od začátku. Při změně sprite_index GameMaker nenuluje image_index, takže by nová animace začala někde uprostřed. End Step proto sprite nejdřív vybere do proměnné novy a vymění ho jen tehdy, když se opravdu liší: if (sprite_index != novy) { sprite_index = novy; image_index = 0; }. Kdyby nuloval pokaždé, animace by zamrzla na prvním snímku.

Kompletní kód pro zvolenou variantu je v oknech v laboratoři výše. Všechno je přímo v událostech objektu, žádné skripty ani funkce navíc. Objekt má tolik událostí, kolik oken vidíš:

obj_hrac

V Asset Browseru potřebuješ sprity spr_hrac_stoji, spr_hrac_beh, spr_hrac_skok, spr_hrac_pad, případně spr_hrac_dopad, a obdélníkový spr_hrac_maska pro kolize. Všechny se stejným originem Bottom Centre. Dál objekty obj_zed a s plošinami i obj_platforma. End Step přidáš v okně objektu přes Add Event → Step → End Step, Animation End přes Add Event → Other → Animation End.

V Godotu oddělíš animaci do vlastní funkce a zavoláš ji až po move_and_slide(). Tehdy už platí is_on_floor() i konečná velocity. play() se stejným jménem animaci nerestartuje, takže ho můžeš volat každý snímek.

@onready var anim: AnimatedSprite2D = $AnimatedSprite2D

func _physics_process(delta):
    # ... pohyb z lekce 2, beze změny ...
    move_and_slide()
    _animuj()

func _animuj():
    if not is_on_floor():
        anim.play("skok" if velocity.y < 0 else "pad")
    elif velocity.x != 0:
        anim.play("beh")
    else:
        anim.play("stoji")
    anim.speed_scale = abs(velocity.x) / MAX_RYCHLOST if anim.animation == "beh" else 1.0
    if velocity.x != 0:
        anim.flip_h = velocity.x < 0

Pro přístup C má Godot uzel AnimationTree se stavovým automatem, který kreslíš myší. Pro začátek stačí funkce výše.

Unity oddělení přímo nabízí: stavový automat (přístup C) nakreslíš v okně Animator a přechody řídíš parametry. Pohybový skript Hrac z lekce 2 zůstane, jen zveřejní, jestli stojí na zemi. Animace má vlastní komponentu, která parametry jen čte a nastavuje v LateUpdate, tedy po všem pohybu.

// v Hrac.cs změň lokální proměnnou na vlastnost:
public bool NaZemi { get; private set; }
// a v Update(): NaZemi = Physics2D.Raycast(...);
using UnityEngine;

[RequireComponent(typeof(Hrac))]
public class HracAnimace : MonoBehaviour {
    Animator anim; Rigidbody2D rb; SpriteRenderer sr; Hrac hrac;

    void Awake() {
        anim = GetComponent<Animator>();
        rb = GetComponent<Rigidbody2D>();
        sr = GetComponent<SpriteRenderer>();
        hrac = GetComponent<Hrac>();
    }

    void LateUpdate() {   // až po veškerém pohybu
        Vector2 v = rb.linearVelocity;
        anim.SetFloat("Rychlost", Mathf.Abs(v.x));
        anim.SetFloat("RychlostY", v.y);
        anim.SetBool("NaZemi", hrac.NaZemi);
        if (Mathf.Abs(v.x) > 0.01f) sr.flipX = v.x < 0;
    }
}

Úkol: postava s animacemi ve vlastním levelu

  1. Najdi nebo nakresli spritesheet postavy a dlaždic. Zdarma a s volnou licencí je najdeš třeba na kenney.nl nebo opengameart.org. Pixelovou postavu si můžeš nakreslit v Piskelu.
  2. Přes Import Strip Image vytvoř sprity spr_hrac_stoji, spr_hrac_beh, spr_hrac_skok a spr_hrac_pad. Všem dej stejnou velikost a origin Bottom Centre. Přidej obdélníkový spr_hrac_maska a v Create ho nastav do mask_index.
  3. Vytvoř Tile Set, v místnosti vrstvu Tiles Zem a nakresli level. Ve Step nahraď obj_zed tilemapou (sekce Tilemapa, záložka GameMaker).
  4. V generátoru v kroku 5 zvol přístup B a zaškrtni, co tvůj projekt má. Okna Create, Step a End Step zkopíruj do stejnojmenných událostí obj_hrac.
  5. Zjisti metriky své postavy (můžeš použít laboratoř v kroku 3) a postav level podle pravidla nauč, procvič, zkomplikuj. Dej ho zahrát spolužákovi bez vysvětlování a sleduj, kde se zasekne.
  6. Bonus: zaškrtni animaci dopadu, přejdi na přístup C a přidej událost Animation End. Nebo přehraj zvuk kroku vždycky, když běh dojde na snímek, kdy se noha dotkne země.
