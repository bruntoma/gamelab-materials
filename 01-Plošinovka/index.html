Pojem 1 · Asset

Asset: dílek ve stavebnici

Asset (čti „eset“) je cokoli, z čeho se hra skládá a co najdeš v projektu: obrázky, zvuky, písma, objekty, scény i skripty. Samy o sobě nic nedělají. Hra vznikne teprve tím, jak je poskládáš dohromady.

Projekt je krabice s Legem. Assety jsou jednotlivé kostičky.

Assety se navzájem používají. Objekt mince potřebuje obrázek mince a zvuk cinknutí. Scéna potřebuje objekty, které v ní budou. Klikni na asset vlevo a podívej se, s čím je propojený.

Tip

Pojmenovávej assety s předponou podle typu: s_ sprite, o_ objekt. V kódu pak hned poznáš, co je co, a nestane se, že se sprite a objekt jmenují stejně (s_player a o_player). Sprity patří v Asset Browseru do složky sprites, objekty do objects.

Assety najdeš v panelu Asset Browser. Nový asset vytvoříš pravým klikem → Create. Typy: Sprites, Sounds, Objects, Rooms, Scripts, Fonts, Tile Sets, Paths, Sequences a další. V kódu se na asset odkazuješ přímo jménem:

// zahraj zvuk (asset snd_coin), priorita 1, neopakovat
audio_play_sound(snd_coin, 1, false);

// přepni na jinou scénu (asset rm_level2)
room_goto(rm_level2);

Assety jsou obyčejné soubory v panelu FileSystem, cesta začíná res://. Obrázky .png, zvuky .wav/.ogg, scény .tscn, skripty .gd. Godot jim říká resources.

# načti zvuk ze souboru a přehraj ho
var zvuk = preload("res://zvuky/mince.wav")
$AudioStreamPlayer.stream = zvuk
$AudioStreamPlayer.play()

Assety jsou v okně Project ve složce Assets/. Do skriptu je obvykle nedostáváš jménem, ale přetáhneš je myší do políčka v Inspectoru.

public AudioClip zvukMince;   // políčko v Inspectoru, přetáhneš sem soubor

void SebralMinci() {
    AudioSource.PlayClipAtPoint(zvukMince, transform.position);
}

Scratch soubory neukazuje. Assety jsou rozdělené do záložek: Kostýmy (obrázky postavy), Zvuky a Pozadí (u scény). Postavy jsou v seznamu pod scénou.

Pojem 2 · Sprite

Sprite: obrázek, který umí pózovat

Sprite je obrázek, kterým se ve hře něco kreslí. Může mít víc snímků (frames). Když se rychle střídají, vznikne animace, stejně jako v kreslené knížce, kterou listuješ palcem.

Sprite má pár důležitých vlastností:

  • Rozměr v pixelech a počet snímků s rychlostí animace (FPS, snímky za sekundu).
  • Origin (počátek): bod, za který sprite „drží“ na souřadnicích x, y. Kolem něj se sprite i otáčí a zrcadlí.
  • Kolizní maska: oblast, která se počítá při nárazech. Nemusí být stejná jako obrázek.

Křížek je poloha instance (x, y). Sprite se nakreslí tak, aby jeho origin ležel přesně na křížku. Zkus origin přesunout a pak sprite otáčet.

Nastavení

!

Sprite neví, kde je, ani co dělá. Je to jen obrázek. Polohu, pohyb a chování mu dává instance objektu, která ho používá. Jeden sprite může používat víc objektů, třeba stejná mince pro „minci“ i „zlatou minci“.

V Sprite Editoru nastavíš snímky, FPS, origin (rozbalovací nabídka nebo klik do obrázku) a Collision Mask. Instance pak sprite ovládá vestavěnými proměnnými:

sprite_index = s_player_run;  // který sprite instance kreslí
image_index  = 0;             // aktuální snímek (od nuly)
image_speed  = 1;             // 1 = rychlost podle FPS spritu, 0 = stop
image_angle  = 45;            // natočení ve stupních, proti směru hodinek
image_xscale = -1;            // zrcadlení: postava se dívá doleva

Obrázek je Texture. Kreslí ho uzel Sprite2D, animace dělá AnimatedSprite2D se sadou SpriteFrames. Origin nastavuješ vlastnostmi centered a offset. Kolize je zvláštní uzel CollisionShape2D.

$AnimatedSprite2D.play("beh")        # spusť animaci "beh"
$AnimatedSprite2D.speed_scale = 1.0   # rychlost animace
$AnimatedSprite2D.flip_h = true       # zrcadlení
rotation_degrees = 45                 # natočení celého uzlu

Obrázek importuješ s Texture Type: Sprite (2D and UI). Origin se jmenuje Pivot (nastavíš ho v Sprite Editoru). Na scéně ho kreslí komponenta SpriteRenderer, animuje Animator a kolize řeší Collider2D.

SpriteRenderer sr = GetComponent<SpriteRenderer>();
sr.sprite = spriteBeh;   // vyměň obrázek
sr.flipX = true;         // zrcadlení
transform.rotation = Quaternion.Euler(0, 0, 45);

Sprite je ve Scratchi kostým. Animace = přepínání kostýmů. Origin je střed kostýmu (v editoru kostýmu ho posuneš tak, že posuneš obrázek vůči středovému křížku).

Pojem 3 · Objekt a instance

Objekt je vykrajovátko, instance jsou perníčky

Objekt je předpis. Říká, jak má věc vypadat (který sprite použije) a jak se má chovat: co udělá, když vznikne, co dělá v každém snímku hry, co se stane, když do ní něco narazí. Těmto situacím se říká události (events).

Instance je jeden konkrétní kus vyrobený podle objektu a umístěný ve scéně. Objekt o_slime máš v projektu jednou, ale slizounů ve scéně může být dvacet.

Všechny instance sdílí chování objektu, ale každá má vlastní proměnné: polohu x, y, počet životů hp. Proto může jeden slizoun zemřít a ostatní žijí dál.

Ve skutečném GameMakeru se změna objektu projeví až po novém spuštění hry. Tady ji vidíš hned, aby bylo jasné, co patří objektu a co instanci.

Objekt vytvoříš v Asset Browseru, přiřadíš mu sprite a přidáš události (Create, Step, Draw, Collision…). Instance přetáhneš myší do scény v Room Editoru, nebo je vytvoříš kódem:

// Create event objektu o_slime: běží jednou, když instance vznikne
hp = 3;

// kdekoli jinde: vytvoř novou instanci na vrstvě "Instances"
var s = instance_create_layer(200, 300, "Instances", o_slime);
s.hp = 10;   // změní hp jen téhle jedné instanci

// počet instancí objektu ve scéně
show_debug_message(instance_number(o_slime));

Godot nemá „objekty“. Předpisem je scéna (.tscn) se skriptem, např. slime.tscn. Instanci vytvoříš přetažením scény do jiné scény, nebo kódem. Pozor: slovo „scéna“ v Godotu znamená předpis i úroveň.

const SlimeScena = preload("res://slime.tscn")

func _ready():
    var s = SlimeScena.instantiate()   # vyrob instanci
    s.position = Vector2(200, 300)
    s.hp = 10                          # jen téhle instanci
    add_child(s)                       # vlož ji do hry

Předpisem je Prefab: GameObject s komponentami, uložený jako asset. Každý GameObject ve scéně je pak instance. Chování píšeš jako komponentu (skript), např. Slime.cs.

public GameObject slimePrefab;   // přetáhni prefab v Inspectoru

void Start() {
    GameObject s = Instantiate(slimePrefab, new Vector3(2, 3, 0), Quaternion.identity);
    s.GetComponent<Slime>().hp = 10;   // jen téhle instanci
}

Objekt je postava. Instance jsou klony: kopie postavy, které běží podle stejných skriptů. Každý klon má vlastní polohu a proměnné „jen pro tuto postavu“.

Pojem 4 · Scéna (room)

Scéna: jeviště, na kterém se hraje

Scéna (v GameMakeru room, místnost) je místo, kde se hra odehrává. Scénou může být úroveň, hlavní menu i obrazovka „Game Over“. Má svou šířku a výšku v pixelech a rozmisťuješ do ní instance objektů.

Scéna se skládá z vrstev. Jsou jako průhledné fólie položené na sobě: dole pozadí, nad ním dlaždice terénu, navrchu instance. Co je ve vyšší vrstvě, překryje to, co je pod ním.

Scéna je divadelní jeviště. Kulisy jsou vzadu, herci vpředu.

Úroveň je také scéna: strom uzlů, ve kterém jsou instance jiných scén (hráč, mince…). Vrstvy řešíš pořadím uzlů ve stromu a vlastností z_index, pozadí třeba uzlem ParallaxBackground, terén TileMapLayer.

Pojem 5 · Kamera a viewport

Kamera: kameraman ve tvé scéně

Scéna bývá mnohem větší než obrazovka. Kamera určuje, kterou část scény právě vidíme. Je to obdélník ve scéně, který má polohu (x, y) a velikost (šířku a výšku).

Viewport je místo na obrazovce, kam se záběr kamery vykreslí. Kamera říká co se snímá, viewport kam a jak velké se to ukáže.

Když kameru zmenšíš a viewport zůstane stejný, obraz se přiblíží. Když se hráč pohne a kamera ho sleduje, vypadá to, že ujíždí celý svět. Ve skutečnosti se hýbe jen kamera.

Díl 2 ze 3Pohyb a kolize

Jak se věci hýbou

Hráč z dílu 1 zatím jen stojí. Aby běžel, skákal a nepropadl podlahou, potřebuje tři kousky: pohyb, gravitaci a kolize. Žádné kouzlo, jen pár řádků, které se opakují šedesátkrát za sekundu.

Každý kousek si nejdřív vyzkoušíš samostatně a v okně s kódem uvidíš, jak se přidává do o_player. Na konci je všechno spojené na hřišti, kde si vyladíš, jak se postava ovládá.

SouřadniceKde věc je. Pohyb je jen změna x a y v každém snímku. RychlostO kolik pixelů se věc posune za jeden snímek. Zrychlení a třeníJak rychle se rozjede a zastaví. Dělá pohyb „těžkým“ nebo „lehkým“. GravitaceKaždý snímek přidá kousek rychlosti směrem dolů. KolizeZjištění, jestli se dvě věci překrývají. Řešení kolizeCo udělat, aby postava stála u zdi a ne v ní.
Krok 1 · Souřadnice a snímky

Pohyb je série malých skoků

Každá instance má polohu x a y v pixelech. Bod (0, 0) je v levém horním rohu scény. x roste doprava a y roste dolů, ne nahoru jako v matematice.

Hra se překresluje zhruba 60× za sekundu. Každému překreslení se říká snímek (frame) a v každém snímku se spustí událost Step. Když v ní napíšeš x += 3, instance se každý snímek posune o 3 pixely doprava. Za sekundu urazí 180 pixelů a oku to splyne v plynulý pohyb.

Jako kreslená knížka: každá stránka je jen o kousek jiná.

Poloha je ve vestavěných proměnných x a y. Rychlost si připravíš v události Create (proběhne jednou, když instance vznikne) a pohyb píšeš do události Step (proběhne v každém snímku). GameMaker má i vestavěné hspeed/vspeed, které posouvají instanci samy, ale vlastní proměnné máš víc pod kontrolou.

Poloha uzlu je position (Vector2). Osa y také roste dolů. Pohyb násob delta (doba snímku v sekundách), aby byl stejně rychlý na pomalém i rychlém počítači.

var rychlost = Vector2(180, -60)   # px za sekundu

func _process(delta):
    position += rychlost * delta

Poloha je transform.position (Vector3). Pozor: v Unity y roste nahoru a jednotkou nejsou pixely, ale „metry“ (obvykle 1 jednotka = 100 px spritu).

public Vector2 rychlost = new Vector2(1.8f, 0.6f);   // jednotek za sekundu

void Update() {
    transform.position += (Vector3)(rychlost * Time.deltaTime);
}

Ve Scratchi je bod (0, 0) uprostřed scény a y roste nahoru. Scéna sahá od x −240 do 240 a od y −180 do 180.

Krok 2 · Rychlost, zrychlení a tření

Rozjezd a brzdění dělají pocit z ovládání

Nejjednodušší ovládání: držíš šipku, postava jede plnou rychlostí. Pustíš ji a postava stojí. Funguje to, ale působí to tvrdě, jako by postava neměla žádnou váhu.

Lepší je měnit rychlost postupně. Zrychlení říká, o kolik rychlost přibude v každém snímku, dokud držíš šipku. Tření říká, o kolik ubude, když šipku pustíš. Malé tření = klouže to jako po ledu. Velké tření = zastaví se hned.

Krok 3 · Gravitace a skok

Gravitace je jeden řádek kódu

Gravitace v plošinovce není nic složitého: v každém snímku přičteš ke svislé rychlosti vsp malé číslo. Postava padá čím dál rychleji, stejně jako kámen.

Skok je opak: jednou nastavíš vsp na záporné číslo (nahoru) a gravitace ho postupně „sežere“. Postava zpomalí, na vrcholu se na chvilku zastaví a začne padat. Vznikne oblouk, kterému se říká parabola.

Aby postava nepadala nekonečně rychle, rychlost pádu se omezí maximem.

Krok 4 · Detekce kolize

Dotýkají se? Stačí čtyři porovnání

Kolize znamená, že se dvě věci překrývají. Engine to většinou nepočítá z obrázku, ale z kolizní masky, což bývá obyčejný obdélník kolem postavy (znáš ho ze spritu v dílu 1). Říká se mu bounding box nebo AABB.

Dva obdélníky se překrývají, právě když platí všechny čtyři podmínky najednou: A začíná před koncem B, A končí za začátkem B, a totéž svisle. Když neplatí jediná, mezi nimi je mezera.

Obdélník je rychlý, ale nepřesný. Zkus postavy přisunout rohy k sobě: obdélníky se překrývají, i když se postavy nedotýkají.

Masku nastavíš v Sprite Editoru (Collision Mask). Hranice masky instance najdeš v bbox_left, bbox_right, bbox_top a bbox_bottom, takže čtyři porovnání z ukázky jdou napsat ručně. Většinou ale použiješ hotovou funkci place_meeting(x, y, obj). Ta zjistí, jestli by došlo ke kolizi, kdyby instance stála na x, y. Když potřebuješ vědět, kterou instanci jsi zasáhl, použij instance_place. Na sbírání mincí stačí událost Collision v objektu hráče.

Parent. Smrtících věcí bývá ve hře víc (slizoun, bodáky, láva). Vytvoř prázdný objekt o_death a všem smrtícím objektům ho v Object Editoru nastav jako Parent. place_meeting(x, y, o_death) pak najde kteréhokoli z nich. Stejně fungují zdi: cokoli s parentem o_wall je pevné.

Krok 1 · Spritesheet

Všechny pózy na jednom archu

V dílu 1 měl sprite několik snímků. Grafici je ale většinou nekreslí do samostatných souborů. Všechny pózy postavy dají do jednoho obrázku a rozmístí je v pravidelné mřížce. Takovému obrázku se říká spritesheet (arch spritů).

Engine pak potřebuje vědět, jak arch rozřezat: jak velký je jeden snímek, kde mřížka začíná (odsazení, offset) a jak široká je mezera mezi snímky (separace). Mezery grafici dělají schválně, aby se při zvětšení nepřelévaly barvy ze sousedních snímků.

Každý řádek archu bývá jedna animace. V GameMakeru z každého řádku uděláš samostatný sprite: s_player_idle, s_player_run, s_player_jump a tak dál. Ty použijeme v celé lekci.

Level jako tabulka čísel

V dílu 2 jsme podlahu skládali z instancí o_wall a každá byla vidět jako šedý čtverec. Hezký svět se ale kreslí jinak: z dlaždic (tiles), malých čtverců stejné velikosti, u nás 32 × 32 px. Dlaždice jsou jen obrázek. O kolize se dál starají objekty, viz níž.

Tileset je spritesheet dlaždic. Každá dlaždice v něm má své číslo. Tilemapa je mřížka přes celou scénu a v každém políčku je jen číslo dlaždice, která se tam nakreslí. 0 znamená prázdno. Celý level je tak tabulka čísel. Uložit ji je snadné a kreslí se rychle.

Ruční skládání krajů a rohů by byla otrava. Proto enginy umí autotiling: ty jen maluješ „tady je zem“ a engine podle sousedů sám vybere správnou dlaždici. Najeď myší na zem a uvidíš, jak to počítá.

Kolize s dlaždicemi

Pohybový skript z dílu 2 se ptá place_meeting(x, y, o_wall) a tak to může zůstat. V Room Editoru přidej nad dlaždice vrstvu instancí, třeba Kolize, a dlaždice v ní překryj instancemi o_wall a o_oneway. Jednu instanci můžeš roztáhnout přes celou podlahu, takže jich nebude moc. U o_wall a o_oneway zruš v Object Editoru zaškrtnutí Visible, ať nepřekreslují dlaždice. Kód hráče se nezmění vůbec.

Když chceš objekt, který se chová jako zeď nebo plošina, třeba rozbitný blok nebo jedoucí plošinu, nastav mu v Object Editoru jako Parent o_wall nebo o_oneway. place_meeting ho pak najde taky.

Alternativa: kolize přímo s tilemapou. place_meeting se umí zeptat i vrstvy s dlaždicemi. Místo objektu jí předáš ID tilemapy a každá neprázdná dlaždice je pevná. Vrstva s instancemi pak není potřeba, ale hůř se tak dělají plošiny a speciální bloky. Kód pro tuhle variantu ukáže přepínač tilemapa v okně s kódem.

Vytvoř asset Tile Set, vyber mu sprite s dlaždicemi a nastav velikost dlaždice, offset a separaci (jako u archu). Autotiling se nastavuje v Tile Set editoru v části Auto Tiling. Pak v Room Editoru přidej vrstvu typu Tiles, pojmenuj ji třeba Zem, přiřaď jí tileset a maluj. Dlaždice 0 je v GameMakeru vždy prázdná.

S vrstvou instancí o_wall nad dlaždicemi zůstává o_player beze změny. Přepni na tilemapa a uvidíš alternativu: kolize se testují s tilemapou zem místo o_wall, a když chceš zdi i dlaždice najednou, předáš pole [o_wall, zem]. Poslední okno ukazuje čtení a zápis dlaždic podle myši v ukázce. Tyhle příkazy můžeš použít v jakékoli události.

Uzel TileMapLayer s prostředkem TileSet. Kolize přidáš v TileSetu jako Physics Layer a na dlaždice nakreslíš tvar. Autotiling se jmenuje Terrains (Terrain Set v režimu Match Corners and Sides). CharacterBody2D s move_and_slide() pak na dlaždicích stojí sám, pohybový kód se nemění.

Krok 3 · Level design

Hráč se má učit hraním

Level design je navrhování úrovní: kam dát plošiny, propasti, nepřátele a mince a co se v nich hráč naučí. Dobrý level hráči nic nevysvětluje textem. Postaví ho do situace, ve které na pravidlo přijde sám.

  • Měř podle postavy. Výška a dálka skoku z dílu 2 určují, jak vysoký smí být schod a jak široká propast. Těmto číslům se říká metriky. Zjisti je dřív, než začneš kreslit.
  • Nauč, procvič, zkomplikuj. Novou věc ukaž nejdřív bez trestu, pak s rizikem a nakonec ve spojení s něčím dalším.
  • Čitelnost. Co je pevné, musí vypadat pevně. Pozadí ztlum, popředí nech kontrastní. Stejná věc vypadá v celé hře stejně.
  • Veď hráče. Řada mincí ukazuje cestu i správný oblouk skoku. Mince na nedostupném místě láká hledat, jak se tam dostat.
  • Rytmus. Střídej napětí a oddech. Po těžké pasáži dej bezpečné místo.

Krok 4 · Animace

Snímky, rychlost a smyčka

Sprite přehrává své snímky dokola. Který snímek se zrovna kreslí, určuje proměnná image_index. Engine k ní v každém snímku hry přičte kousek podle rychlosti animace. Je to desetinné číslo a kreslí se snímek podle celé části: 2,33 znamená snímek 2.

Rychlost má dvě části. FPS spritu nastavíš v Sprite Editoru: kolik snímků animace se přehraje za sekundu. image_speed je násobek: 1 = normálně, 0,5 = poloviční rychlost, 0 = stop.

Pozor na klouzání nohou. Když postava běží rychle a nohy se hýbou pomalu, vypadá to, jako by bruslila. Pomůže svázat rychlost animace s rychlostí pohybu.

Některé animace se nemají opakovat: dopad, útok, smrt. Když animace dojede na konec, GameMaker spustí událost Animation End. V ní animaci zastavíš nebo přepneš na jinou.

FPS nastavíš v Sprite Editoru vlevo nahoře. V kódu pracuješ s vestavěnými proměnnými instance: sprite_index (který sprite), image_index (který snímek), image_speed (násobek rychlosti) a image_number (počet snímků, jen ke čtení). Každá animace v SpriteFrames má vlastní FPS a přepínač Loop. Konec neopakované animace ohlásí signál animation_finished.

@onready var anim: AnimatedSprite2D = $AnimatedSprite2D

func _ready():
    anim.play("beh")
    anim.speed_scale = 0.5               # poloviční rychlost
    anim.animation_finished.connect(_on_konec)

func _on_konec():
    if anim.animation == "dopad":
        anim.play("stoji")

Animace je přepínání kostýmů. Rychlost určuje čekání: 0,1 s mezi kostýmy = 10 snímků za sekundu.

V Godotu oddělíš animaci do vlastní funkce a zavoláš ji až po move_and_slide(). Tehdy už platí is_on_floor() i konečná velocity. play() se stejným jménem animaci nerestartuje, takže ho můžeš volat každý snímek.

@onready var anim: AnimatedSprite2D = $AnimatedSprite2D

func _physics_process(delta):
    # ... pohyb z dílu 2, beze změny ...
    move_and_slide()
    _animuj()

func _animuj():
    if not is_on_floor():
        anim.play("skok" if velocity.y < 0 else "pad")
    elif velocity.x != 0:
        anim.play("beh")
    else:
        anim.play("stoji")
    anim.speed_scale = abs(velocity.x) / MAX_RYCHLOST if anim.animation == "beh" else 1.0
    if velocity.x != 0:
        anim.flip_h = velocity.x < 0

Pro přístup C má Godot uzel AnimationTree se stavovým automatem, který kreslíš myší. Pro začátek stačí funkce výše.

Unity oddělení přímo nabízí: stavový automat (přístup C) nakreslíš v okně Animator a přechody řídíš parametry. Pohybový skript Hrac z dílu 2 zůstane, jen zveřejní, jestli stojí na zemi. Animace má vlastní komponentu, která parametry jen čte a nastavuje v LateUpdate, tedy po všem pohybu.

// v Hrac.cs změň lokální proměnnou na vlastnost:
public bool NaZemi { get; private set; }
// a v Update(): NaZemi = Physics2D.Raycast(...);
using UnityEngine;

[RequireComponent(typeof(Hrac))]
public class HracAnimace : MonoBehaviour {
    Animator anim; Rigidbody2D rb; SpriteRenderer sr; Hrac hrac;

    void Awake() {
        anim = GetComponent<Animator>();
        rb = GetComponent<Rigidbody2D>();
        sr = GetComponent<SpriteRenderer>();
        hrac = GetComponent<Hrac>();
    }

    void LateUpdate() {   // až po veškerém pohybu
        Vector2 v = rb.linearVelocity;
        anim.SetFloat("Rychlost", Mathf.Abs(v.x));
        anim.SetFloat("RychlostY", v.y);
        anim.SetBool("NaZemi", hrac.NaZemi);
        if (Mathf.Abs(v.x) > 0.01f) sr.flipX = v.x < 0;
    }
}

V Animatoru pak vytvoř stavy Stoji, Beh, Skok, Pad a přechody s podmínkami, třeba Stoji → Beh když Rychlost > 0.1, cokoli → Skok když NaZemi = false a RychlostY > 0.

GameMaker v každém snímku spouští události v pevném pořadí. Když dáš výběr animace do End Step, máš jistotu, že pohyb i kolize už proběhly a hsp, vsp i poloha jsou pro tenhle snímek konečné. Animace pak ukazuje, co se opravdu stalo, ne co se hráč pokusil udělat.

Úkol: postava s animacemi ve vlastním levelu

  1. Najdi nebo nakresli spritesheet postavy a dlaždic. Zdarma a s volnou licencí je najdeš třeba na kenney.nl nebo opengameart.org. Pixelovou postavu si můžeš nakreslit v Piskelu.

  5. Zjisti metriky své postavy (můžeš použít laboratoř v kroku 3) a postav level podle pravidla nauč, procvič, zkomplikuj. Dej ho zahrát spolužákovi bez vysvětlování a sleduj, kde se zasekne.
